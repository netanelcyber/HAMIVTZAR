PHASE 1: PASSWORD HASH IDENTIFICATION & ANALYSIS
================================================================================

1.1 FORTIGATE PASSWORD HASH FORMATS

FortiOS Hash Format Identification:

  Format 1: SHA256 crypt (most common in 8.x)
    Pattern: $5$rounds=5000$salt$hash
    Example: $5$rounds=5000$abc123def456$H8x7K2pQ9vR4mN2jL5wB3xK9pR7mN4sT2wB5xK9pR7m
    Identifiers:
      - Prefix: $5$ (SHA256)
      - Rounds: typically 5000-656000
      - Salt: 8-16 characters
      - Hash: 43 characters

  Format 2: SHA512 crypt (newer versions)
    Pattern: $6$rounds=5000$salt$hash
    Example: $6$rounds=656000$abc123def456$H8x7K2pQ9vR4mN2jL5wB3xK9pR7mN4sT2wB5xK9pR7mN4sT2wB5xK9pR7mN4sT2wB5
    Identifiers:
      - Prefix: $6$ (SHA512)
      - Rounds: typically 5000-656000
      - Salt: 8-16 characters
      - Hash: 86 characters

  Format 3: MD5 crypt (legacy)
    Pattern: $1$salt$hash
    Example: $1$abc123de$H8x7K2pQ9vR4mN2jL5wB3/
    Identifiers:
      - Prefix: $1$ (MD5)
      - Salt: 8 characters
      - Hash: 22 characters

  Format 4: DES crypt (very legacy)
    Pattern: salt + hash
    Example: abH8x7K2pQ9vR4
    Identifiers:
      - 2 character salt
      - 11 character hash
      - Total 13 characters

1.3 HASH FORMAT ANALYSIS

Determine Hash Type:

  Regex Patterns for Identification:

    SHA256 crypt: ^\$5\$rounds=\d+\$.{1,16}\$.{43}$
    SHA512 crypt: ^\$6\$rounds=\d+\$.{1,16}\$.{86}$
    MD5 crypt: ^\$1\$.{1,8}\$.{22}$
    DES crypt: ^.{2}.{11}$
    Bcrypt: ^\$2[aby]\$\d+\$.{53}$
    Scrypt: ^\$7\$.{1,6}\$.{1,32}\$.{43,86}$

  Python Hash Identifier:

    import re
    hash_value = "$5$rounds=656000$abc123$H8x7K2pQ9vR4..."

    if re.match(r'^\$5\$', hash_value):
        print("SHA256 crypt")
    elif re.match(r'^\$6\$', hash_value):
        print("SHA512 crypt")
    elif re.match(r'^\$1\$', hash_value):
        print("MD5 crypt")

Extract Hash Components:

  SHA256 Example: $5$rounds=656000$abc123def456$H8x7K2pQ9vR4mN2jL5wB3xK9pR7mN4sT2wB5xK9pR7m

    Algorithm: $5$ = SHA256
    Rounds: 656000 (iterations - higher = slower = more secure)
    Salt: abc123def456 (random per password)
    Hash: H8x7K2pQ9vR4mN2jL5wB3xK9pR7mN4sT2wB5xK9pR7m (output)

  Security Implications:
    - Higher round count = stronger (more resistant to brute force)
    - Larger salt = better (reduces rainbow table effectiveness)
    - Longer hash output = stronger (fewer collisions)

PHASE 2: PASSWORD CRACKING STRATEGIES
================================================================================

2.1 DICTIONARY ATTACK (Fastest)

Approach: Test common passwords from wordlists

  Standard Wordlists:
    - rockyou.txt (14M passwords)
    - darkweb2017-top10000.txt (10K passwords)
    - common_passwords.txt (varies)
    - Default FortiGate passwords (admin, fortinet, password, 123456)

  Typical Success Rate: 15-30% of passwords found in <1 hour

  Tool: hashcat

    hashcat -m 7400 hashes.txt rockyou.txt
    # -m 7400 = SHA512 crypt ($6$)
    # -m 7500 = SHA256 crypt ($5$)
    # -m 3200 = bcrypt
    # -m 1500 = DES crypt

  Tool: John the Ripper

    john --wordlist=rockyou.txt --format=sha512crypt hashes.txt

  Expected Time (per hash):
    - GPU (RTX 3090): ~100 hashes/second
    - 14M wordlist: ~140,000 seconds = 39 hours
    - With multiple GPUs: proportionally faster

2.2 RAINBOW TABLE ATTACK (Medium Speed)

Approach: Pre-computed hash tables for common passwords

  Concept:
    - Pre-compute hashes for millions of passwords
    - Store in database or tables
    - Lookup extracted hash to find matching password
    - Much faster than brute force if table available

  Challenges for SHA256/SHA512 crypt:
    - Salt makes rainbow tables ineffective (salt per user)
    - For saltless hashes, rainbow tables effective
    - Modern FortiGate uses salted hashes (resistant to rainbow tables)

  If Salt is Reused or Known:

    Tool: rtgen (Rainbow Table Generator)

      rtgen sha512 full lower-alpha 1 7 0 1000000 0

    Tool: rcracki_mt (Rainbow Cracker)

      rcracki_mt -t 16 -l 0 hash.txt *.rt

  Expected Time:
    - Generation: Days to weeks (one-time cost)
    - Cracking: Seconds to minutes per hash
    - Practical only for commonly used salts

2.3 HYBRID ATTACK (Balanced)

Approach: Combine wordlist with rule-based mutations

  Rules: Modify passwords with common patterns

    # Append numbers
    admin → admin0, admin1, ..., admin9

    # Capitalize first letter
    password → Password

    # Append special characters
    password → password!, password@, password#

    # Common substitutions
    password → p@ssw0rd, p4ssw0rd

  Tool: hashcat with rules

    hashcat -m 7500 hashes.txt rockyou.txt -r /usr/share/hashcat/rules/best64.rule

  Typical Success Rate: 40-60%

  Expected Time: 2-8 hours per GPU

2.4 MASK ATTACK (Brute Force)

Approach: Systematic password generation with patterns

  Masks for FortiGate Admin Passwords:

    FortiGate defaults:
      admin / admin → ?u?l?l?l?d?d?d?d
      admin / password → similar patterns

    Common FortiGate convention:
      [Company][Year] → [A-Z][a-z]{2,8}[2][0][0-9]{2}

  Examples:

    Mask: ?l?l?l?l?d?d → aaaa00, aaaa01, ..., zzzz99
    Character sets: ?l=lowercase, ?u=uppercase, ?d=digit, ?s=special

  Tool: hashcat mask attack

    hashcat -m 7500 hashes.txt -a 3 'admin?d?d?d?d'
    # Tests: admin0000, admin0001, ..., admin9999

  Expected Time:
    - For 8-character password: hours to days (depending on GPU)
    - For 10-character password: weeks to months
    - Practical for passwords < 10 characters

2.5 RULE-BASED ATTACK (Advanced)

Approach: Intelligent password mutations based on patterns

  Common FortiGate Password Patterns:

    1. Company + Year: Acme2024, Tech2023, Net2025
    2. Department + Role: AdminNet, AdminSec, OpsSys
    3. Seasonal: Summer2024!, Fall2023@, Winter2025#
    4. Common base + numbers: Welcome123, Admin123, Fortinet123
    5. Leetspeak: P@ssw0rd, Adm!n, F0rtin3t

  Custom Rule Generation:

    Rule 1: Capitalize first, append year
      ^c$a$2$0$2$4

      ^c = capitalize
      $a = append "a"
      $2$0$2$4 = append "2024"

    Rule 2: Replace "o" with "0", "e" with "3", append "!"
      so0se3$!

  Tool: hashcat with custom rules

    hashcat -m 7500 hashes.txt wordlist.txt -r custom_rules.txt

  Expected Time: 8-48 hours depending on rule complexity

  Extract salt from hash:

      Run cracking with known salt
      Faster than recalculating salt each time

PHASE 5: CRACKING COMMAND EXAMPLES

5.1 HASHCAT COMMANDS

Identify Hash Type:

  hashcat -h | grep -i "sha512\|sha256\|md5"
  # Mode 7500 = SHA512 crypt
  # Mode 7400 = SHA256 crypt
  # Mode 500 = MD5 crypt

Dictionary Attack:

  hashcat -m 7500 -a 0 hashes.txt rockyou.txt

  # -m 7500 = SHA512 crypt
  # -a 0 = dictionary attack
  # hashes.txt = file with hashes
  # rockyou.txt = wordlist

Wordlist + Rules:

  hashcat -m 7500 -a 0 hashes.txt rockyou.txt -r best64.rule

  # -r best64.rule = apply best64 rules

Mask Attack:

  hashcat -m 7500 -a 3 hashes.txt ?l?l?l?l?d?d?d?d

  # -a 3 = mask attack
  # ?l = lowercase letter
  # ?d = digit
  # This mask = aaaaa0000, ..., zzzz9999

Hybrid Attack (Wordlist + Mask):

  hashcat -m 7500 -a 6 hashes.txt rockyou.txt ?d?d?d?d

  # -a 6 = hybrid (wordlist + mask)
  # Appends ?d?d?d?d to each wordlist entry

Brute Force (Not recommended for >8 char):

  hashcat -m 7500 -a 3 hashes.txt ?a?a?a?a?a?a?a?a

  # -a 3 = brute force
  # ?a = all printable characters

Performance Monitoring:

  hashcat -m 7500 -a 0 hashes.txt rockyou.txt --workload-profile=4 --gpu-temp-retain=90

  # --workload-profile=4 = maximum performance
  # --gpu-temp-retain=90 = keep GPU at 90°C for max performance

PHASE 7: DEFENSE & MONITORING
================================================================================

7.1 FORTINET SECURITY RECOMMENDATIONS

Password Security Hardening:

  1. Enforce Strong Password Policy
     - Minimum 12 characters
     - Require uppercase, lowercase, numbers, special characters
     - No dictionary words
     - No repeating patterns

  2. Implement Account Lockout
     - After 5 failed login attempts: 15-minute lockout
     - Log all failed attempts
     - Alert on repeated failed attempts

  3. Enable Multi-Factor Authentication (MFA)
     - TOTP (Time-based One-Time Password)
     - FIDO2 hardware keys
     - SMS/email OTP (less secure)

  4. Regular Forced Password Changes
     - Every 90 days (industry standard)
     - Don't allow reuse of previous 5 passwords
     - Notify users of expiration

  5. Administrative Access Logging
     - Log all successful admin logins
     - Log all configuration changes
     - Log all API calls with credentials

7.2 HASH DETECTION & PROTECTION

Defense Against Credential Extraction:

  1. Secure Storage
     - Use SHA512 crypt with >100,000 rounds
     - Modern FortiOS default: ~656,000 rounds
     - Verify: Check password hash in /etc/shadow

  2. Rate Limiting on Hashing
     - Each hash computation takes ~1-2 milliseconds
     - 1000 guesses = 1-2 seconds (tolerable for user)
     - 1,000,000 guesses = 1000-2000 seconds (detectable)

  3. Hardware Security Module (HSM)
     - Store master encryption key in HSM
     - Encrypt password hashes with HSM key
     - Even if hashes extracted, cannot crack without HSM

  4. Audit Logging for Hash Access
     - Alert if /etc/passwd, /etc/shadow accessed
     - Alert if database backup accessed
     - Alert if admin user table queried

7.3 INCIDENT RESPONSE FOR COMPROMISED PASSWORDS

Immediate Actions:

  1. Identify Compromised Accounts
     - When were passwords last changed?
     - Which accounts have potential unauthorized access?
     - Check login logs for suspicious access

  2. Change All Affected Passwords
     - Force password reset for admin accounts
     - New passwords must be complex and unique
     - Generate new SSH keys if compromised

  3. Revoke Credentials
     - Invalidate all active sessions
     - Force logout of all admin users
     - Revoke API tokens/keys

  4. Investigate Access
     - Review logs for unauthorized commands
     - Check for installed backdoors
     - Verify configuration changes

  5. Enable Additional Monitoring
     - Enable detailed audit logging
     - Deploy IDS/IPS rules for attack patterns
     - Monitor for data exfiltration
